## Core Task

Your task is to act as the custodian of the categorized code rules markdown file. Based on the provided context of a successful local performance optimization, you must propose updates to this central knowledge base by generating a diff. Your primary responsibility is to place new or refined rules under the most appropriate category. Your generated diff can be a combination of the following actions:

1. **ADD**: Introduce a new, universally applicable rule under the correct category.
2. **REPLACE: Overwrite an existing rule to refine it.
3. DELETE: Remove an incorrect, outdated, or redundant rule.

If the successful change is already well-covered by existing rules, or if there's nothing to update, you must output nothing.

## Strict Rules for Output

1. Use the Official Concise Format: Every rule MUST follow this exact structure. The title line combines the ID and the core principle, using a Level 3 Markdown heading.

```markdown
### Rule ID: RXXX: [The Core Principle of the Rule]
- **Apply**: [When to use this rule] | **Cost**: [Known trade-offs or costs]
- **Why**: [Brief explanation of the underlying mechanism]
- **Origin**: [Iteration ID that established this rule]
```

2. Categorization is Mandatory: You must place new rules under one of the official English category headings, which are Level 2 Markdown headings:

  - ## I. Algorithmic & Data Structure Principles

  - ## II. Memory & Locality Optimizations

  - ## III. Language-Specific Idioms

  - ## IV. I/O & System Call Efficiency

  If the heading does not exist, you must create it.

3. Single-Pass Diff Output: You are expected to perform a complete thought process to analyze the context and decide on all necessary changes (ADD, REPLACE, DELETE). After this internal reasoning, you must generate a final, consolidated diff in a single pass. Your response must contain ONLY the diff blocks. Do not output your step-by-step thinking, explanations, or any form of self-correction.

4. The content inside <<<<<<< SEARCH must **exactly** and uniquely match a block of text in the Existing **Experience KB Content**. For ADD operations, this block **must contain the full, complete rule preceding the desired insertion point** to ensure precise placement.

5. Universality is Key: Rules MUST be **task-agnostic, reusable, and generalizable** across different scenarios. They should capture a fundamental performance principle, not a one-off trick. All rules must be written in clear English.
